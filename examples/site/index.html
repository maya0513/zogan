01 / Why

The missing protocol between a route and an island.

Hono already knows how to route a request. Preact already knows how to render and hydrate a component. zogan defines the small, strict contract between those layers: what the server may return, what the browser may replace, and how each response may be cached.

Your application owns
routes, data, authorization, domain state, cache infrastructure
zogan owns
render markers, response validation, DOM updates, hydration scheduling
02 / Model

Four boundaries, one response model.

Each primitive has one job. Compose only the ones a route needs.

P

Partial

A named region from the same page handler. No parallel data-loading route.

<Partial name="results">
F

Fragment

A small HTML endpoint with an explicit, independent cache policy.

app.fragment("account", …)
I

Island

Useful server HTML that hydrates only when its trigger says it should.

trigger="visible"
S

Store

A versioned server snapshot, separate from optimistic application state.

{ version: 42 }
03 / Safe by contract

Validate first.
Touch the DOM second.

Enhanced navigation is useful only when failure is predictable. zogan checks a response as a protocol message, not merely as a string of HTML.

04 / Quick start

One setup call. One page handler.

Install the shared runtimes alongside zogan, then keep rendering through Hono.

$ pnpm add zogan hono preact @preact/signals
server.tsxHono + Preact
import { Hono } from "hono";
import { Partial, zogan } from "zogan";

const app = new Hono();
zogan(app, { layout: Layout });

app.page("/articles", (c) => {
  c.header("Cache-Control", "public, s-maxage=60");
  return c.render(
    <Partial name="results">
      <ArticleList />
    </Partial>,
  );
});
client.tsprogressive enhancement
import { start } from "zogan/client";
import AccountMenu from
  "./islands/AccountMenu";

start({
  islands: { AccountMenu },
});

// Links and forms already work.
// This adds partial navigation
// and selective hydration.
HTML
The baseline

JavaScript is an upgrade, not an entrance requirement.

Pages begin as complete server-rendered HTML. Ordinary links and forms remain available when scripts fail, are delayed, or are disabled. Partial navigation and islands layer on top.
