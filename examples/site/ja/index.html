明示的なHTML、型付きIsland

ページを描画する。
ブラウザに任せる。

zoganはHonoとPreactに、明示的なPageとFragment response、必須のcache境界、lazyな型付きIslandを提供します。リンク、フォーム、ナビゲーション、履歴の所有者はブラウザのままです。

01 / 目的

HTML境界を小さく、明確な契約にする。

1つのURLには1つの表現だけを持たせます。Pageはdocument、Fragmentは専用route、Islandは明示的なownerです。serverとbrowserが別のnavigation modelを同期する必要はありません。

アプリケーションが所有
route、data、認可、mutation、domain state
ブラウザが所有
link、form、redirect、navigation、history
zoganが所有
HTML response factory、明示的marker、activation scheduling
02 / モデル

4つの明示的な境界。隠し事はない。

各primitiveには1つの役割だけがあります。routeは必要な境界だけを組み合わせます。

C

Cache

すべてのHTML responseに検証済みのopaque CachePolicyが必要です。

publicCache({ sMaxAge: 60 })
P

Page

doctypeと任意のapplication layoutを持つ完全なdocumentです。

zogan.page(c, view, { cache })
F

Fragment

専用routeのraw HTMLを1つのFragmentSlotへ配置します。

<FragmentSlot src="/fragments/cart" />
I

Island

server fallback、JSON props、triggerで読み込む型付きcomponentです。

<Island of={counter} props={...} />
03 / 明示的な契約

先に宣言する。
その後で拡張する。

Cache、Fragment target、Island ownership、lazy component lookupがapplication codeに現れます。契約を証明できない拡張では、server-rendered fallbackが残ります。

  1. 01 表現ごとに1つの通常のHono route
  2. 02 すべてのHTML responseにCachePolicy
  3. 03 root-relativeでsame-originなFragment source
  4. 04 Island propsはplain JSON object
  5. 05 descriptor IDとlazy-loader IDを一致
04 / クイックスタート

2つのresponse factory。通常のroute。

各responseでcacheを宣言し、必要なFragmentSlotとIslandだけを追加します。

$ pnpm add zogan hono preact
server.tsx明示的なHTML route
import { createZogan, FragmentSlot, publicCache } from "zogan";

app.get("/", (c) => zogan.page(
  c,
  <FragmentSlot src="/fragments/cart">
    <a href="/cart">Cart —</a>
  </FragmentSlot>,
  { cache: publicCache({ sMaxAge: 60 }) },
));
Island + client.ts型付きでlazy
const counter = defineIsland<CounterProps>({
  id: "Counter", component: Counter,
});

<Island of={counter} props={{ initial: 0 }}
  trigger="visible" />

// browser entry
start({ islands });
startFragments();
