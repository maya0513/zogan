# §9 実装順序

各段階で動く EC を作れることを確認してから次へ進む。

1. **`app.page` + マーカー付き SSR**（差し替えなし、フルリロードのみ）
   - この時点で SEO・LCP 要件は満たせている
2. **Island のハイドレーション**（`data-island`、trigger 5 種、コンポーネント登録）
   - [§1](01-scope.md) で「作らないもの」に挙げた *loader*（ルート階層のデータ取得）とは無関係。ここで作るのは名前からコンポーネントを引く registry だけ
3. **Partial の差し替え**（`data-client-nav` オプトイン、`X-Partial`、複数領域、AbortController、フォールバック）
   - 検証：ファセット絞り込みが URL 更新 + 部分差し替えで動く
4. **Store**（base + pending + snapshot マージ）
   - 検証：カート追加 → 別商品へ遷移 → バッジが維持されている
5. **Fragment + キャッシュヘッダ + [§5.5](05-store.md) の照合ミドルウェア**
   - 検証：商品ページが CDN キャッシュされた状態でカート数が正しく出る
   - 検証：そのキャッシュを別ユーザが受け取っても snapshot が漏れない
6. **mode（append/prepend）+ key 検証**、**preserve**、**navigating signal**
7. **client-only 検証のビルドプラグイン**（[§5.3](05-store.md)、`zogan/vite`）

### 9.1 この順序の根拠

**各段階の終わりで「動く EC」が手に入る**ことが唯一の設計基準です。段階の途中で止まっても、そこまでで商品を売れる状態になっています。

| 段階 | 完了時点で作れるもの | 何が無いか |
|---|---|---|
| 1 | SSR された EC。全ページフルリロード | 対話性 |
| 2 | 対話する EC。カートボタンが動く | 遷移が速くない |
| 3 | ファセット絞り込みが速い EC | 遷移でカートがちらつく |
| 4 | カートが遷移を跨いで維持される EC | CDN キャッシュが効かない |
| 5 | **CDN にキャッシュされる EC**（← 本命） | 無限スクロール等 |
| 6 | 一通り揃った EC | ビルド時の安全網 |
| 7 | 事故を機械的に防げる EC | — |

段階 5 が zogan の存在意義そのものです（[§4.1](04-fragment.md)）。**そこまでは全部前提条件**だと考えてください。

### 9.2 順序を入れ替えてはいけない箇所

| 制約 | 理由 |
|---|---|
| **4（Store）は 5（Fragment）より前** | Fragment の応答に snapshot が載る（[§5.2.2](05-store.md)）。Store が無いと Fragment の設計が決まらない |
| **3（Partial 差し替え）は 4 より前** | Store のマージは差し替え処理の中に組み込まれる（[§7.2](07-client-runtime.md) のステップ 8） |
| **2（Island）は 4 より前** | Store を読む場所が Island しかない（[§5.4](05-store.md)） |
| **7（ビルドプラグイン）は最後でよい** | 安全網であり機能ではない。ただし**段階 4 の直後にリスクが発生する**ので、4 以降は [§10](10-acceptance.md) の負荷テストで代替すること |

最後の行は注意が必要です。段階 4 で Store を導入した時点から [§5.3](05-store.md) の事故が起こりえます。段階 7 まで安全網がない期間があるので、**その間はコードレビューと負荷テストで守ってください。**

### 9.3 段階 4 → 5 の移行に固有の危険

**段階 4 の時点では、まだ殻に snapshot を置けてしまいます。** この段階ではキャッシュヘッダを入れていないので、`app.page` の応答に `<StoreSnapshot>` を置いても実害が出ません。段階 4 の完了条件（カート追加 → 遷移 → バッジ維持）は、Partial の内側に snapshot を置く実装で素直に通ります。

そして**段階 5 で殻を `public, s-maxage=300` にした瞬間、[§5.5](05-store.md) の違反になります**。他人のカートが CDN 経由で配信され始めます。段階 4 で通っていたテストは全部通り続けるため、気付く契機がありません。

対処：

- **[§5.5](05-store.md) の照合ミドルウェアを段階 5 の一部として実装する。** 「安全網は後回し」の例外はここだけです
- 段階 4 の時点から snapshot を Fragment の応答に置く設計にする。段階 5 で Fragment を作るまでは、キャッシュヘッダを入れない `app.page` から出しておき、**段階 5 で移す前提で書く**
- [§10](10-acceptance.md) の 11 番（CDN 経由の漏洩）を段階 5 の完了条件に含める

### 9.4 各段階の完了判定

「動く」の定義を曖昧にしないため、段階ごとの完了条件を置きます。

| 段階 | 完了条件 |
|---|---|
| 1 | 商品一覧・商品詳細・カート・レジが SSR で表示され、Lighthouse の SEO が満点 |
| 2 | カートボタンが動作し、`visible` trigger のギャラリーがスクロールで初期化される |
| 3 | ファセットを切り替えると URL が変わり、結果だけが差し替わる。JS を無効にしても同じ操作ができる |
| 4 | カート追加 → 別商品ページへ遷移 → バッジが維持され、ちらつかない |
| 5 | 商品ページに `age` ヘッダ（CDN ヒット）が付いた状態で、ログインユーザに正しいカート数が出る。**かつ、その CDN キャッシュを別ユーザが受け取っても前者のカートが出ない**（[§10](10-acceptance.md) の 11） |
| 6 | 無限スクロールで重複描画が起きない。動画再生中に遷移しても止まらない |
| 7 | Store をサーバから import した状態でビルドすると、到達パス付きのエラーで失敗する |
